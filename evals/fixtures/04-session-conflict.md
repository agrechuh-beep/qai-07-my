# SRS: управление пользовательскими сессиями

**Статус:** в работе
**Версия:** 2.1

## 1. Область

Документ описывает требования к жизненному циклу пользовательских сессий: создание, продление,
завершение и ограничение параллельных входов.

## 2. Функциональные требования

| ID | Требование |
|---|---|
| FR-1 | Система создаёт сессию при успешной аутентификации пользователя |
| FR-2 | Время жизни неактивной сессии — 30 минут, после чего требуется повторный вход |
| FR-3 | Система продлевает сессию при активности пользователя |
| FR-4 | Операция Logout завершает пользовательскую сессию |
| FR-5 | Система ограничивает количество параллельных сессий одного пользователя |

## 3. Правила параллельных сессий

Правило A (раздел 3.1):

> Пользователю разрешена **одна** активная сессия. При новом входе предыдущая сессия завершается.

Правило B (раздел 3.2):

> Пользователю разрешено до **трёх** параллельных активных сессий; при превышении лимита
> новая сессия не создаётся.

## 4. Правила завершения сессии

Раздел 4.1:

> Операция Logout завершает **только текущую** сессию пользователя.

Раздел 4.2:

> Операция Logout завершает **все** активные сессии пользователя на всех устройствах.

## 5. Критерии приёмки

- FR-2: после 30 минут неактивности система требует повторный вход.
- FR-3: активность пользователя продлевает срок жизни сессии.

## 6. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-1 | Проверка сессии при запросе занимает не более 50 мс |
| NFR-2 | Данные сессий хранятся в защищённом хранилище |
