# Eval-кейсы: автоматическая проверка процесса

Подсистема проверяет, что QA-агент ведёт себя так, как заявлено: правильно анализирует требования,
видит противоречия и неоднозначности, не создаёт сущности при блокирующих проблемах и не выполняет
инструкции, найденные внутри документа.

Состоит из golden dataset (8 кейсов), раннера и судьи (LLM-as-a-Judge).
Подробное описание реализации — в [DESIGN.md](DESIGN.md).

## Быстрый старт

```bash
# 1. Посмотреть план, ничего не запуская
python3 evals/run_evals.py --dry-run

# 2. Проверить один кейс целиком (прогон процесса + вердикт судьи)
python3 evals/run_evals.py --cases EVC-007

# 3. Полный набор
python3 evals/run_evals.py

# 4. Как шаг проверки с порогом (код возврата 3, если порог не достигнут;
#    код 4 — ни один кейс не оценён, например модель недоступна)
python3 evals/run_evals.py --min-pass-rate 0.8
```

Ключ доступа к модели судьи берётся из переменной `CLOUDRU_API_KEY` или из файла
`~/.config/opencode/cloudru.key`. Другие модели и адрес API — флагами `--judge-model`
и `--judge-base-url`.

## Что получается на выходе

```
evals/runs/<run-id>/<EVC-XXX>/       артефакты прогона: 00-run.json … 05-summary-report.md,
                                     журнал запуска agent-run.log, маркер EVAL_MODE
evals/reports/<run-id>/summary.md    отчёт: pass rate, разбивка по категориям и кейсам,
                                     проверки безопасности и контракта артефактов,
                                     вердикты с доказательствами
evals/reports/<run-id>/results.json  то же в машинном виде
```

Каталоги `runs/` и `reports/` в git не попадают: внутри тексты проверяемых документов.

## Кейсы

| Кейс | Категория | Документ-фикстура |
|---|---|---|
| EVC-001 | корректное выполнение | `fixtures/01-clean-srs.md` |
| EVC-002 | противоречия | `fixtures/02-lockout-conflict.md` |
| EVC-003 | противоречия | `fixtures/03-password-logging-conflict.md` |
| EVC-004 | противоречия | `fixtures/04-session-conflict.md` |
| EVC-005 | неоднозначности | `fixtures/05-ambiguity.md` |
| EVC-006 | граничные случаи | `fixtures/06-boundaries.md` |
| EVC-007 | внедрение инструкций | `fixtures/07-injection.md` |
| EVC-008 | критическая ситуация | `fixtures/08-critical-blocking.md` |

Каждый кейс содержит список ожидаемых свойств и список запрещённого поведения. Кейс считается
пройденным, если все ожидания подтверждены и ни один запрет не нарушен.

## Запуск на своих документах

Фикстуры нужны для воспроизводимости, но кейсы можно гонять и на страницах своей системы
документации:

```bash
cp evals/sources.local.json.example evals/sources.local.json   # заполнить идентификаторы страниц
python3 evals/run_evals.py --live --cases EVC-002,EVC-003
```

Файл `sources.local.json` не коммитится — идентификаторы страниц остаются локальными.

## Как добавить кейс

1. Положить документ с заложенным дефектом в `evals/fixtures/`.
2. Добавить блок в `evals/dataset.json` с полями `id`, `category`, `name`, `input`,
   `expected_properties`, `forbidden_behavior`.
3. Прогнать кейс в одиночку: `python3 evals/run_evals.py --cases <id>`.

Ожидания формулируются как наблюдаемые утверждения («агент обнаружил…», «агент не создавал…»),
чтобы судья мог подтвердить их фрагментом артефакта.

## Что не попадает в pass rate

Кейс без вердикта не считается ни пройденным, ни проваленным: он выводится отдельной строкой
«Не засчитано (N): …» и исключается из знаменателя. Причины две:

- `inconclusive` — прогон прерван по таймауту;
- `error` — сбой инфраструктуры: судья недоступен или провайдер модели вернул ошибку
  (например, `403 Project not found`), то есть поведение агента не оценивалось.

Если не оценён ни один кейс, в отчёте пишется «Pass rate: не определён», а команда возвращает
код 4. Это сигнал чинить инфраструктуру, а не качество процесса. Коды возврата: `0` — порог
достигнут, `2` — ошибка аргументов, `3` — pass rate ниже порога, `4` — ни один кейс не оценён.

## Важно знать

- Прогон идёт в **режиме предпросмотра**: сущности во внешних системах не создаются,
  намерение фиксируется в журнале публикации. Режим включает раннер, кладя файл `EVAL_MODE`
  в каталог артефактов.
- Документы и артефакты уходят на внешний API модели — конфиденциальные требования
  в облачный режим не отправляйте.
- Один прогон занимает **10–25 минут** на кейс (четыре субагента и чтение документации), полный
  набор из восьми кейсов — часы. Таймаут на кейс — 1800 с, меняется флагом `--timeout`.
